# 02 · M2 增量同步与变更检测

## 一、实现目标

在 M1「全量采集」基础上，增加**增量同步**能力：

1. 每次采集后，与元数据库现有记录对比；
2. 识别三类变更：新增、修改、删除；
3. 只处理变更部分（新增/修改写库，删除做软删除 `is_deleted=1`）；
4. DDL 变更写入 `md_change_log`。

### 验收标准
- 重复采集同一库，第二次无变更时不产生任何写入；
- 修改字段类型/注释能被识别并记录；
- 删除的表/字段被软删除而非物理删除；
- 每次变更都有 `md_change_log` 记录。

## 二、详细开发过程

### 步骤 1：建变更日志表

在 `sql/` 追加（或新建 `002_create_change_log.sql`）：

```sql
USE metadata_db;

CREATE TABLE md_change_log (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  instance_id   BIGINT UNSIGNED NOT NULL,
  database_name VARCHAR(128) NOT NULL,
  table_name    VARCHAR(128) NULL,
  column_name   VARCHAR(128) NULL,
  change_type   VARCHAR(32) NOT NULL COMMENT 'ADD / MODIFY / DELETE',
  object_type   VARCHAR(32) NOT NULL COMMENT 'DATABASE / TABLE / COLUMN / INDEX',
  old_value     TEXT NULL COMMENT '变更前（JSON）',
  new_value     TEXT NULL COMMENT '变更后（JSON）',
  changed_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_log (instance_id, database_name, table_name)
) COMMENT='DDL/结构变更日志';
```

### 步骤 2：差异比对器（`agent/diff/differ.py`）

核心思路：以**唯一键**为基准做集合对比。

- `md_table` 唯一键：`(database_name, table_name)`；
- `md_column` 唯一键：`(database_name, table_name, column_name)`。

```python
from dataclasses import dataclass, field

@dataclass
class DiffResult:
    added_tables: list = field(default_factory=list)
    modified_tables: list = field(default_factory=list)
    deleted_tables: list = field(default_factory=list)
    added_columns: list = field(default_factory=list)
    modified_columns: list = field(default_factory=list)
    deleted_columns: list = field(default_factory=list)
```

比对流程：

```python
async def diff(self, instance_id: str, new_metas: list[DatabaseMeta]) -> DiffResult:
    # 1. 从 md_table / md_column 读出该实例已有记录
    old_tables = await self.repo.load_tables(instance_id)
    old_columns = await self.repo.load_columns(instance_id)

    # 2. 构建新旧集合（key -> 记录）
    new_table_map = {t.table_name: t for t in new_tables}
    old_table_map = {t.table_name: t for t in old_tables}

    # 3. 表级对比
    for name, t in new_table_map.items():
        if name not in old_table_map:
            result.added_tables.append(t)          # 新增表
        elif self._table_changed(old_table_map[name], t):
            result.modified_tables.append(t)        # 修改表（注释/引擎等变化）
    for name in old_table_map:
        if name not in new_table_map:
            result.deleted_tables.append(name)      # 删除表

    ...
```

字段"修改"判定：比较 `column_type / is_nullable / column_default / column_comment` 等任一不同即算修改。

```python
def _column_changed(self, old: ColumnMeta, new: ColumnMeta) -> bool:
    return (
        old.column_type != new.column_type
        or old.is_nullable != new.is_nullable
        or old.column_default != new.column_default
        or old.column_comment != new.column_comment
    )
```

### 步骤 3：应用 diff 结果

按 diff 分类执行：

- **新增**：`INSERT` 到 md_table / md_column；
- **修改**：`UPDATE` 对应记录；
- **删除**：`UPDATE ... SET is_deleted=1`（软删除）。

```python
async def apply(self, instance_id, diff: DiffResult):
    for t in diff.added_tables:     await self.repo.insert_table(instance_id, t)
    for t in diff.modified_tables:  await self.repo.update_table(instance_id, t)
    for name in diff.deleted_tables:await self.repo.soft_delete_table(instance_id, name)
    # 字段同理
    await self.repo.write_change_logs(diff)   # 记录变更日志
```

### 步骤 4：变更日志记录

每次变更都写入 `md_change_log`，`old_value/new_value` 用 JSON 序列化差异字段，便于溯源。

```python
{
  "object_type": "COLUMN",
  "change_type": "MODIFY",
  "old_value": {"column_type": "varchar(32)", "column_comment": ""},
  "new_value": {"column_type": "varchar(64)", "column_comment": "用户名"}
}
```

### 步骤 5：接入主流程

```python
async def run_sync():
    mysql_client_manager.init()
    try:
        metas = await collector.collect()          # M1 采集
        diff = await differ.diff(instance_id, metas)  # M2 比对
        await differ.apply(instance_id, diff)         # M2 应用
        print(diff.summary())
    finally:
        await mysql_client_manager.close()
```

## 三、关键注意点

- **唯一键是比对基础**，M1 建表时务必把唯一键建对，否则 diff 会误判；
- 表被删除后，其下字段应一并软删除（或直接依赖表级 `is_deleted`，字段无需单独删）；
- 字段顺序变化（`ordinal_position`）是否算"修改"要提前定义——通常不视为业务变更，可忽略；
- `column_default` 存在二进制/表达式默认值时，序列化 JSON 要转字符串，避免类型报错；
- 比对要带上 `instance_id`，否则多实例（M4）数据会串。
