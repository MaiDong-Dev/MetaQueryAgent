# 05 · M5 向量库业务域归类

## 一、实现目标

引入 Milvus 向量库，通过**字段语义相似度**辅助归类业务域，提升 M3 中 LLM 对业务域的识别准确率与一致性。

核心价值：
1. 业务域归类不靠 LLM"拍脑袋"，而是与历史已确认的字段向量做相似度检索，结果更稳定；
2. 支持"字段 → 业务域"的推荐，人工确认后反哺向量库，形成持续优化闭环。

### 验收标准
- 能对字段名生成向量并写入 Milvus；
- 给定新字段，能检索出最相似的 Top-K 已归类字段及其业务域；
- 检索结果能作为 LLM 补全业务域的参考输入。

## 二、详细开发过程

### 步骤 1：环境准备

- 部署 Milvus（本地可用 `docker` + `milvusdb/milvus`，或 `milvus-lite` 嵌入式）；
- 引入 SDK：`pymilvus`、`sentence-transformers`（或调用 Embedding 接口，如 DeepSeek 不支持 embedding 时用 `text2vec` 类模型）。

```bash
uv add pymilvus
```

### 步骤 2：向量化（`agent/vector/embedder.py`）

字段语义向量来源有两种选择：

- **方案 A（本地模型）**：`sentence-transformers` 加载中文 embedding 模型（如 `BAAI/bge-small-zh`），离线、免费、可控；
- **方案 B（在线接口）**：调用 OpenAI 兼容的 embedding 接口。

```python
from sentence_transformers import SentenceTransformer

class Embedder:
    def __init__(self):
        self.model = SentenceTransformer("BAAI/bge-small-zh-v1.5")

    def embed(self, texts: list[str]) -> list[list[float]]:
        return self.model.encode(texts, normalize_embeddings=True).tolist()
```

> 向量输入文本建议用「表名 + 字段名 + 字段注释」拼接，语义更丰富。

### 步骤 3：Milvus Collection 设计（`agent/vector/milvus_store.py`）

```python
from pymilvus import connections, Collection, CollectionSchema, FieldSchema, DataType

def init_collection():
    connections.connect(alias="default", host="localhost", port="19530")
    fields = [
        FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
        FieldSchema(name="column_text", dtype=DataType.VARCHAR, max_length=512),
        FieldSchema(name="business_domain", dtype=DataType.VARCHAR, max_length=64),
        FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=512),
    ]
    schema = CollectionSchema(fields, description="字段语义向量")
    col = Collection("column_domain", schema)
    # 建立向量索引
    col.create_index("embedding", {"index_type": "IVF_FLAT", "metric_type": "IP", "params": {"nlist": 128}})
```

> `dim` 必须与 embedding 模型输出维度一致（bge-small-zh 为 512）。

### 步骤 4：写入与检索

```python
# 写入：人工确认业务域后，把字段向量入库
def upsert(self, texts, domains):
    vectors = self.embedder.embed(texts)
    col.insert([texts, domains, vectors])

# 检索：给定新字段，找最相似的业务域
def search_domain(self, text: str, top_k=3):
    vector = self.embedder.embed([text])[0]
    res = col.search([vector], "embedding", {"metric_type": "IP"}, limit=top_k)
    return [hit.entity.get("business_domain") for hit in res[0]]
```

### 步骤 5：接入 M3 补全流程

在 LLM 补全业务域前，先用向量检索候选域，作为 Prompt 的辅助信息：

```python
candidates = vector_store.search_domain(f"{table}.{column}")
prompt = build_prompt(table, candidates)   # "该字段候选业务域: 订单域/用户域"
```

LLM 结合候选域 + 字段语义给出最终业务域，结果更稳定。

### 步骤 6：人工确认反哺

平台中人工修正业务域后，把修正结果重新写入向量库，逐步提升检索准确率。

## 三、关键注意点

- **向量维度必须与模型一致**，否则建库/写入报错；
- 中文 embedding 建议用 `bge-small-zh` / `text2vec` 类中文模型，英文模型对中文字段语义效果差；
- 向量库是"辅助推荐"，**最终业务域仍以 LLM + 人工确认为准**，不要用向量结果直接覆盖；
- 初始冷启动时向量库为空，可先跑 M3 让 LLM 直接归类，人工确认一批后再入库，逐步预热。
