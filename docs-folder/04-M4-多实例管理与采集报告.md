# 04 · M4 多实例管理与采集报告

## 一、实现目标

1. **多实例**：一套 Agent 可管理多个业务 MySQL 实例（每个实例独立连接配置），采集/比对/补全按 `instance_id` 隔离；
2. **采集报告**：每次同步结束输出可读报告（新增/修改/删除多少表、字段，AI 补全多少）。

### 验收标准
- 能配置并同时管理 2+ 个业务实例，互不串数据；
- 同步完成后输出结构化报告（控制台 + 可落库/导出）。

### 步骤 2：按实例建连接

现有 `mysql_client_manager` 是**单例单连接**，多实例需要支持多引擎。两种方案：

- **方案 A（推荐）**：`mysql_client_manager` 改造为按实例名缓存引擎的工厂：

```python
class MysqlClientManager:
    def __init__(self):
        self._engines: dict[str, AsyncEngine] = {}
        self._sessions: dict[str, async_sessionmaker] = {}

    def get_session_factory(self, instance_name: str):
        if instance_name not in self._sessions:
            conf = self._get_conf(instance_name)
            engine = create_async_engine(self._url(conf), ...)
            self._sessions[instance_name] = async_sessionmaker(engine, ...)
        return self._sessions[instance_name]

    async def close_all(self):
        for e in self._engines.values():
            await e.dispose()
```

- 方案 B：每个实例独立创建 `MysqlClientManager` 实例，由上层字典管理。

> 建议用方案 A，保持"单例管理所有实例"的风格。

### 步骤 3：主流程按实例循环

```python
async def run_all():
    for inst in schema_conf.instances:
        await run_instance(inst.name)

async def run_instance(name: str):
    session_factory = mysql_client_manager.get_session_factory(name)
    collector = SchemaCollector(session_factory)
    metas = await collector.collect()
    diff = await differ.diff(name, metas)      # instance_id 用 name 或 md_instance.id
    await differ.apply(name, diff)
    enriched = await enricher.enrich_all(diff.changed())
    await biz_repo.save(name, enriched)
    report = build_report(name, diff, enriched)
    print(report)
```

### 步骤 4：采集报告（`agent/report/reporter.py`）

报告数据结构：

```python
@dataclass
class SyncReport:
    instance_name: str
    crawl_time: datetime
    added_tables: int
    modified_tables: int
    deleted_tables: int
    added_columns: int
    modified_columns: int
    deleted_columns: int
    enriched_tables: int
    enriched_columns: int
    llm_failed: int
```

修改表：1

> 报告可进一步落库到 `md_sync_report` 表（可选），或导出 markdown 数据字典（后续扩展）。

## 三、关键注意点

- 所有元数据表查询/写入必须带 `instance_id`（或实例名），否则多实例数据串；
- 采集账号建议统一使用只读账号 `meta_reader`，元数据库写入用另一套高权限账号；
- 密码明文存 yaml 仅适合内网/开发，生产建议用环境变量或密钥管理；
- 实例异常（连不上）不应导致整体退出，单个实例失败要捕获并记录，继续处理其他实例。
